## Why a file

A new engineer learns how a team works over several weeks, from colleagues. An agent starts each task knowing only what it reads at the start of that task, so a way of working that lives in a wiki or in people's heads is invisible to it.

`AGENTS.md` is an open convention for exactly this: a file at the root of a repository that coding agents read before they do anything else. CanonBall uses it to carry the method.

## The files an agent reads first

| File | What it gives the agent | Who owns it |
|---|---|---|
| `AGENTS.md` | How work moves here | People |
| [`tenets.md`](../tenets/) | How this team chooses when two good things conflict | People |
| [`vocabulary.md`](../vocabulary/) | What each word means | People |

An agent reads all three before every task; what else it reads depends on the task.

## The top part is yours

The top of the file is specific to the repository. Keep it to what an agent needs on every task: what the system is, the commands, and who decides what. This is the top part of the refunds service's `AGENTS.md`, without its table of owners.

````markdown
## This repository

**What the system is.** The refunds service of an online shop. It decides each refund request a customer
makes, and pays approved refunds through the payment gateway. Money is in cents in code and in dollars in
prose.

**Commands.**

```text
tools/canonball check     is the canon well formed, and is every example checked?
tools/canonball run       run every check in VE-002 and record the evidence
tools/canonball fault verify/faults/NAME.patch
                          run the checks against an injected fault; keep the red proofs
tools/canonball record    the Verification Record for spec/
tools/canonball status    the state of every milestone and unplanned item

observe/tools/observe decisions --order N [--log PATH]
                          the decisions logged for an order (default log: $REFUNDS_DECISION_LOG)
observe/tools/observe replay --order N [--log PATH]
                          re-run those decisions with the current code
```

VE-002, the verification environment, is `verify/envs/ve002.py`. Constructing a `World` brings it up
(an in-memory store, a fake payment gateway, a decision log); `close()` takes it down. Its four verbs are
`rig`, `act`, `perturb` and `observe`. Python 3.11 or later, standard library only.

**Code.** Decision logic in `src/refunds/decide.py`, with no side effects. The service, which reads, logs,
records and pays, in `src/refunds/service.py`. Adapters in `src/refunds/adapters/`. See
`spec/blueprint/architecture.md`.

**Who decides what here.**

| Decision | Who |
|---|---|
| Promises, product decisions, invariants, constraints | People, always |
| Architecture | the architect |
| Detailed design | agents, recorded in `spec/blueprint/` |
| Verification design | the verification lead, with the verifier |
| What counts as critical | `spec/canon/policy/review.md` |
````

The "who decides what" table records the team's settings. [Handing over decisions](../delegation/) explains how they move.

## Keeping it true

The appendix is useful only while it matches how the team works, so a team that changes a rule changes the appendix in the same milestone. People own the file, and a change to it is reviewed by a person.

Agents that keep asking the same question, or keep making the same wrong assumption, are a sign that the file is missing something. The answer goes in `AGENTS.md` if it is about how work moves, in `tenets.md` if it is about a trade-off, and in `vocabulary.md` if it is about a word.
