## What arrives

A one-page proposal: refunds under $100 are approved automatically. It reads clearly and hides two decisions.

## A word nobody defined

Before drafting a clause, the elicitor checks every noun in the proposal against `vocabulary.md`. One is missing. Under $100 of what: the order, or the refund?

It asks the product manager, with the two readings side by side. The answer goes into the vocabulary.

```text
Refund amount   The money returned by one refund. Not the order total.
```

An agent that guessed would have built one of the two readings, and nobody would have known which until a customer complained.

## An example exposes a choice

The elicitor writes examples for the proposed decision. One has no obvious answer.

> Given an order of $150, when the customer asks for $60 back, and later for another $60, then what?

Each refund is under $100. Together they are not, and the proposal does not say which counts.

The elicitor recommends counting everything refunded on the order, and cites the first of the team's [tenets](../tenets/): a person's review over speed, when money moves. The product manager agrees.

The decision is recorded as a clause, with the examples that fix its meaning.

```markdown
id: DEC-031
kind: decision
traces: [REQ-012]
---
A refund is approved automatically while the total
refunded on the order stays under $100.

Why: tenet 1.

Satisfies:
- A $40 refund, nothing refunded before: approved without review.
- Two $60 refunds on one order: the second goes to review.
Violates:
- A $250 refund approved without review.
```

The risk team's request is now an example that a check will enforce.

## How it will be built

Who leads the design is each team's choice. This team's architect keeps the architecture and leaves detailed design to the agents.

The architect makes one call: the new rule belongs in the **decision logic**, the part of the code that decides and touches nothing outside, and the code that pays out is not changed. The planner agent writes the rest of the design, with a **predicted change in behavior**:

> A refund moves from review to automatic approval while the total refunded on the order stays under $100. Nothing else changes.

At Review, the orchestrator compares this prediction with what actually changed.

## How it will be proven

The **evidence plan** is written now, before the code. Scientists register a hypothesis before an experiment for the same reason: a test written after the code can be shaped to fit it.

The verification lead and the verifier agent decide what the test must cover. The existing environment, VE-002, can set up an order, but not one that has already been partly refunded, so they add that starting state. VE-002 can already make its fake gateway lose a reply after paying. The plan says the automatic path must be run against that failure too, because a careless retry there would pay twice.

## The agreement gate

A **gate** is a point where a person must act before work moves on. This one closes the station.

| Who | Approves |
|---|---|
| Product manager | The three examples for DEC-031 |
| Constraint owner | That ENV-003, the payout limit, is untouched |
| Verification lead | The evidence plan, including how the case for INV-004 covers the automatic path |

People approve examples. There is no code yet to approve.
