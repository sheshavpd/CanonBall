## The four layers

<Figure id="layers" />

Canon and blueprint together form the **spec**, the statement of intent; build and Verification Record describe what exists. Agents keep the two consistent and report when they cannot.

Read down the left side, each layer constrains the one below: the canon bounds what the blueprint may design, and the blueprint bounds what the build may contain.

Read up the right side, each layer answers to the one above. The build produces evidence, and the blueprint holds, for each clause, an **assurance case**: the argument for how that clause will be shown true. The evidence discharges the cases, and the cases discharge the clauses in the canon.

When two layers disagree, the higher one is correct by definition, and the change is blocked until they agree.

## Canon

The canon is the set of approved [clauses](../primitives/), plus a few pages that give them context: the purpose of the system, who it serves, the [vocabulary](../vocabulary/), and the [tenets](../tenets/), which say which good thing wins when two conflict.

It is written in plain language and is the only layer people must read in full; the others are read by exception.

## Blueprint

The blueprint is where design choices are written down, so that they stay visible and can be reversed. It holds:

- the architecture and the contracts between internal modules;
- **derived decisions**, which are design choices an agent made and recorded with its reasons;
- one case per clause;
- the evidence plan and the design of each verification environment.

The canon leaves gaps on purpose, so that design need not wait on a person for every detail, and the blueprint records how each was filled. Agents may revise the blueprint freely, provided it never contradicts the canon.

A person can move a derived decision up into the canon at any time, which is how a design choice is taken back from the agents: once promoted to a [decision](../primitives/#decision), it changes only when a person changes it. A team can also keep parts of the design with a person from the start, as [Handing over decisions](../delegation/) describes.

## Build

The build has two halves. `src/` is the code that runs, written by the builder agent at the [Build](../build/) station. `verify/` is everything that produces evidence (environments, checks, injected faults, proofs and monitors), written by the verifier agent at the [Verify](../verify/) station.

The agent that writes `src/` can run `verify/` but cannot change it, for reasons given in [People and agents](../people-and-agents/).

Both agents examine the running system through `observe/`, which sits beside the two halves, lists what the system emits and holds the tools that read it, as [Observability](../observability/) describes.

The build may be changed freely, with one restriction: it may not be regenerated from the spec. The spec leaves many things open, and a fresh generation would settle each of them again, differently, so the build changes only through a sequence of checked changes.

## Verification Record

The Record states, for every clause, whether the evidence supports it. The orchestrator, a program, computes it from the cases and the results of the checks, according to rules that people own.

Nobody can write "done" or "verified" into the Record, because it is not a file in the repository; it is recomputed on every push and published. The [release rule](../release/) is stated in terms of it.

## Two rules that make it mechanical

The layers are held together by two automated checks that run on every change.

> **Traceability.** Every element of the build refers to an element of the blueprint, and every element of the blueprint refers to a clause. Anything that cannot be traced blocks the merge.

This check establishes only that the references exist; whether they justify the code is a question for the case.

> **No silent gaps.** No clause is reported as accepted while any part of its case lacks evidence. Anything that has not been assessed is shown as unknown and is never left out.

Both rules are computed, and neither depends on a person.
