## What arrives

A reviewed milestone. Nothing at this station is done by a person or decided by an agent. A program applies a rule.

## The release rule

Checks for a milestone run against the **release candidate**: `spec/` with the milestone's proposed files applied. The milestone may be released when two things are true of the Verification Record computed for that candidate.

1. Every clause the milestone touches is accepted.
2. No clause it did not touch has become worse.

The second condition is what protects everything already promised. A milestone carries no list of things it must not break. The Record enforces every clause, every time.

## What the program does

When the rule holds and the review has passed, a program does four things.

1. Copies the files in `diff/` over the files of the same name in `spec/`.
2. Archives the milestone folder.
3. Publishes a CanonBall.
4. Deploys the build that CanonBall names.

No person edits `spec/` by hand, at any time. That is why `spec/` can be trusted to describe the system as it is.

## What a CanonBall holds

```text
CanonBall 13
  canon    spec/canon at this release
  build    commit 3f9c
  record   4 accepted, 0 unsupported
  notes    + DEC-031 Refunds under $100 are approved automatically
```

Three things, fixed together at one moment: what the system promises, the code that keeps the promises, and the evidence that it does. Any one of them without the other two answers less. Together they answer "what does this system promise, and how do you know?" without anyone reading code. [What a CanonBall is](../canonball/) goes further.

Progress is a sequence of them. The service was at CanonBall 12. It is now at 13.

## When the rule does not hold

The milestone stays on the belt. The Record names the clause that is holding it and the part of that clause with no evidence, so the work goes back to a specific place.

| What the Record shows | Where the milestone goes |
|---|---|
| A touched clause is unsupported | [Verify](../verify/), for the missing evidence |
| A check fails | [Build](../build/) |
| An untouched clause got worse | [Build](../build/), or [Review](../review/) if someone means to accept it |

Nobody argues about whether the milestone is done. The status is computed.

## What leaves

`spec/` now describes a system in which small refunds are approved automatically, and that system is running. It is [operated](../operate/) from here.
