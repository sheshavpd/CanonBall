## A sentence is not a specification

"A refund is never issued twice for the same order" reads as a complete rule. It leaves at least three things open. Is a second, partial refund on the same order "twice", or only a repeat of the same refund? What about two requests that arrive together, before either has been paid? What about a payout that went through while its reply was lost, so the client tries again?

Each answer is a decision. If the sentence is all you approve, an agent makes those decisions for you.

## What an example is

An **example** is one concrete case of a clause, written in a fixed shape: *given* a starting state, *when* something happens, *then* an outcome.

```gherkin
Given a $40 refund for order 4471 has been paid
When the client sends the same refund request again
Then the customer has been paid $40, once
```

The practice is known as specification by example, and behavior-driven development calls each case a *scenario*. Every clause has examples of two kinds.

| Kind | Shows |
|---|---|
| **Satisfies** | A situation in which the clause holds. |
| **Violates** | A situation the clause forbids. |

The violating examples do most of the work. "Two concurrent requests both pay out" tells the reader more about what "never twice" means than the sentence does.

## People approve examples

In CanonBall a person never approves a formal statement, and never approves a bare sentence. A person approves examples. The sentence is accepted only through the cases that pin it down.

This puts human attention where it counts. The step from prose to a precise property is the one step no tool can check. If the property is wrong, every check built on it verifies the wrong thing perfectly. Examples let a person confirm the meaning before any of that machinery is built.

The approval happens at the [Shape station](../shape/), where an agent drafts the examples for a milestone and people settle them. The station ends at the **agreement gate**, where a person agrees to what the system will promise.

## From an example to a check

<Figure id="example-flow" />

Each example becomes one check, built at the [Verify station](../verify/), and the check names the example it encodes. That link is enforced. An example with no check shows up as a gap. A check with no example has no reason to exist.

For every violating example, the check must also be seen to fail once, against a deliberately broken build. The chapter on [evidence](../evidence/) explains why.

## Conventions that help agents read

Compression works only when the writer and the reader share a codebook. These conventions fix the codebook. An agent enforces them while drafting and points out where a clause departs from them.

### Sentence shapes for promises

Five shapes cover nearly every promise. They come from a requirements notation called EARS, the Easy Approach to Requirements Syntax.

| Shape | Pattern |
|---|---|
| Always | The system shall ... |
| On an event | When *trigger*, the system shall ... |
| In a state | While *state*, the system shall ... |
| Unwanted case | If *condition*, then the system shall ... |
| Optional feature | Where *feature* is present, the system shall ... |

### Words with one meaning

**Must**, **must not**, **should** and **may** each mean one thing, as they do in internet standards. *Must* is binding. *Should* marks a default that can be overridden for a recorded reason. *May* marks an option.

### Plain prose, said back

One idea per sentence, active voice, and quantities with units: "within 200 ms", never "quickly". Words such as "appropriate" and "as needed" each hide a decision.

After drafting a clause, the agent restates it in its own words. If the restatement surprises the author, the clause is reworked before anyone approves it.

## What an example cannot do

Examples pin down meaning at the points you thought to write. They say nothing about the points you did not. A clause with five examples can still be wrong in a sixth situation.

The agent proposes extra examples, and every incident adds the one that was missing. Examples make a missing case cheap to add. They do not tell you it is missing.
