# Assurance case: INV-004

INV-004: a refund is never issued twice for the same order. "Twice" means the same request paid two times.

## Parts

| Part | Claim | How it is supported |
|---|---|---|
| P1 | A repeated request never pays again: a request sent twice, retried after a lost reply, or arriving in two concurrent copies leads to one payout attempt sequence under one request key. | Checked in VE-002: INV-004 satisfies/1, satisfies/2 and violates/1, each seen to fail against an injected fault. |
| P2 | The gateway pays once per request key. | Assumed: ASM-011. Watched in production by `verify/monitors/duplicate-payouts.md`. VE-002's fake gateway behaves as ASM-011 says. |

## Argument

A refund is paid twice only if the gateway transfers money twice for one request. The service sends every
payout for a request under that request's key (P1), and the gateway transfers at most once per key (P2). So
for the same request, at most one transfer happens. P1 covers everything the service controls; P2 is the one
thing it does not, which is why it is an assumption with a monitor rather than a check.

VE-002 cannot show whether the real gateway honors request keys. That is the residual risk, and it is the
risk the monitor watches.
